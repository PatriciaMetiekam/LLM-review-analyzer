LLM Review Analyzer — Анализ отзывов клиентов с помощью LLM-workflow

Проект по курсу «Автоматизация работы с большими генеративными моделями» (этап 1/8).

ЦЕЛЬ

Анализировать отзывы клиентов с помощью LLM и сравнить две архитектуры:
1. One-shot — один вызов LLM (baseline)
2. Sequential workflow — 3 специализированных вызова по цепочке

Результат структурирован в JSON и провалидирован через Pydantic.

АРХИТЕКТУРА

Отзыв клиента
   |
   v
[Шаг 1: Тональность] --> {sentiment, confidence}
   |
   v
[Шаг 2: Аспекты] --> [{category, polarity, quote}]
   |
   v
[Шаг 3: Резюме + рекомендация]
   |
   v
[Валидация Pydantic] --> финальный JSON

ТЕСТОВЫЙ НАБОР

10 отзывов клиентов:
- 8 стандартных случаев (положительный, отрицательный, нейтральный, смешанный)
- 2 нестандартных случая: сарказм и очень короткий отзыв (эмодзи)

РЕЗУЛЬТАТЫ СРАВНЕНИЯ

Метрика                     One-shot    Workflow
Доля успешных выполнений    100%        90%
Accuracy (тональность)      100%        100%
Среднее время, с            1.96        2.57
Среднее число вызовов LLM   1           3
Средний расход токенов      372         550

ВЫВОДЫ

1. One-shot лучше в данном случае: быстрее, дешевле, надёжнее.
2. Workflow не даёт выигрыша в качестве: accuracy одинаковая.
3. Workflow добавляет риск: на тесте 9 (сарказм) шаг 2 вернул невалидный JSON.
4. Рекомендация: для этой простой задачи предпочтителен one-shot. Workflow оправдан для более сложных задач.
